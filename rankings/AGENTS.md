## Second Quint Rankings app

Spec: `../.scratch/rankings/spec.md`. Tickets: `../.scratch/rankings/issues/`. Vocabulary: `../GLOSSARY.md`.

### Running

- `npm run db:start`: start local Supabase (Docker) and write `.env.local`
- `npm run dev`: app at http://127.0.0.1:3000
- `npm run db:reset`: re-apply all migrations from scratch
- New schema: `npx supabase migration new <name>`, then edit the file in `supabase/migrations/`
- Sample catalog: `supabase/seed.sql` and `public/samples/` are generated by `node scripts/generate-sample-data.mjs`; edit the script, not the outputs

### Layout

- `src/domain/`: pure rules and calculations, no I/O (bracket building, ranking calculation, allowance math)
- `src/server/`: the game, catalog, and admin services; take a `SupabaseClient` as their first argument
- `src/app/`: pages, route handlers, and server actions; thin wrappers over `src/server/`
- `src/lib/supabase/`: `createVisitorClient()` (acts as the visitor, respects row-level security) and `createAdminClient()` (server-only, full access)

- `src/lib/session.ts`: who is playing. `readPerson()` / `ensurePerson()` give the signed-in player or the signed-out visitor; game service functions take either (`Person`). `src/proxy.ts` refreshes the Supabase session cookies.

`cacheComponents` is off: pages render dynamically.

### Environment variables

`npm run db:start` writes all of these to `.env.local` for local work; production values go in Vercel.

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: the Supabase project, safe for the browser
- `SUPABASE_SECRET_KEY`: full-access key for `createAdminClient()`, server-only
- `SUPABASE_DB_URL`: direct Postgres connection, used by scripts only
- `RANKINGS_REFRESH_SECRET`: shared secret for `POST /api/rankings/refresh` (bearer token). Supabase pg_cron calls it every 5 minutes using the URL and secret stored in Vault (`rankings_refresh_url`, `rankings_refresh_secret`); without both Vault secrets the job does nothing, as locally. Setup: `docs/ops.md`

### Global rankings

The ranking refresher (`refreshGlobalRankings` in `src/server/rankings.ts`) recomputes every global ranking with the pure calculation in `src/domain/ranking/` and stores one ready-made list per scope and version (`ranking_lists.rated`: rated lists use only rated matches, unrated lists every match; `ranking_entries`); ranking pages only read those rows, showing the rated version unless the URL has `?version=unrated`. The default category cover is the top of the category's rated list. Service tests call `refreshGlobalRankings` directly instead of waiting for the schedule.

### Personal rankings and profiles

`getPersonalRanking` (`src/server/rankings.ts`) computes a player's personal ranking on every request from only their own non-excluded matches, with no fading (`halfLifeDays: null`); nothing is stored and the refresher isn't involved. `listPersonalRankingScopes` lists Overall plus the categories they've played. The profile (`/players/[name]`, `?scope=<category ID>`, `?version=unrated`) shows these and `listPastTournaments` (`src/server/game.ts`, latest 50) to anyone through the visitor client.

### Rated allowance

The allowance size and the New York day boundaries are pure (`src/domain/allowance/`); `tournamentRatedStatus` decides rated or unrated with the reason, and the start page uses it to tell the player before starting. The game service enforces it in the `start_tournament` SQL function, which locks the player's row so the one-unfinished-rated-tournament check and the reservation in `allowance_use` (per player, scope, and day; only ever added to) can't race. Service functions take an optional `now` so tests can cross midnight. Tournament picks never touch `allowance_use`, so a rated tournament resumed on a later day stays rated for free. `giveUpTournament` sets status `given_up` (only from an unfinished rated tournament) and refunds nothing; `pickWinner` and `undoLastPick` only update unfinished tournaments, so they can't revive one. `UnfinishedTournaments` (`src/app/unfinished-tournaments.tsx`) is the resume banner on the home page, the player's own profile, and the start page.

### Infinite Mode

`getInfinitePair` offers each person one pair per scope, stored in `infinite_pairs` so a reload shows the same pair; `pickInfiniteWinner` and `skipInfinitePair` delete that row first (so a pair is picked or skipped once), and the next `getInfinitePair` draws a new pair with the pure `pickInfinitePair` (`src/domain/infinite/pairing.ts`) using the scope's latest stored rated ranking list. A signed-in player's pick is rated while they have allowance left in the scope: the `pick_infinite_pair` SQL function claims the pair, adds 1 to `allowance_use`, and records the match in one transaction, locking the player's row like `start_tournament`. While a pick would be rated, skips are limited to `RATED_SKIPS_PER_DAY` (5) per player per New York day across all scopes (`skip_use`, enforced by `skip_infinite_pair`); unrated skips are unlimited. Choosing unrated (`?play=unrated`, the `unrated` option) gives a separate offered pair (`infinite_pairs.chose_unrated`), so free unrated skips can't clear the rated pair. `getInfinitePair` returns `play`: rated with picks and skips left, or the unrated reason. Infinite Mode never checks for an unfinished rated tournament. Pages: `/infinite` (scope list) and `/infinite/[scope]` (`all` or a category ID).

### Catalog and pictures

The catalog service (`src/server/catalog.ts`) adds and edits contestants and categories and enforces who may edit what (rules in `src/domain/catalog/permissions.ts`). Pictures are resized in the browser by `src/lib/picture/resize.ts` to center-cropped squares at 512 and 128 px (WebP; JPEG where the browser can't encode WebP), using the pure rules in `src/domain/picture/picture.ts`, which a server-side import with `sharp` can reuse. The server stores them in the public `pictures` Storage bucket (created by a migration) under the SHA-256 of their bytes, cached for a year. `contestants.source_id` is an internal, unique ID for bulk-imported contestants (e.g. `mal:12345`), never shown.

### Test seams

- **Unit** (`npm test`): `src/**/*.test.ts`, pure domain code, including the ranking calculation
- **Service** (`npm run test:service`): `tests/service/**/*.test.ts`, calls `src/server/` against the local Supabase; files run one at a time
- **Browser** (`npm run test:e2e`): `e2e/*.spec.ts`, Playwright at a phone viewport against a production build; keep these few and about wiring, not rules. `e2e/auth-stub.ts` signs a browser in without Google (admin-issued magic link), so the app has no test-only sign-in route
